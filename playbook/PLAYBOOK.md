# 视频制作 Playbook

版本：`0002`

这套 Playbook 不是另一个剪辑软件。它规定视频从想法到复盘必须经过什么阶段、每阶段交什么文件、什么情况下不能继续。

## 不变原则

1. 一条视频只服务一个核心问题。
2. 参考只复用结构和节奏，不复制品牌、文案和未授权素材。
3. 每个阶段都必须产出文件，聊天记录不是正式交付物。
4. 上一阶段门禁未通过，不进入下一阶段。
5. 成片结论必须来自真实媒体轨道和真实渲染文件。
6. 封面一律由 GPT 设计：先按剧情出封面底图与标题文案，再用
   `scripts/make-episode-cover.mjs` 配版式，不使用模板化口号。

## 文件与状态

每条视频任务单独建一个工程目录，至少包含：

```text
brief.json
reference.json
material-plan.json
shotbook.json
component-plan.json
qa.json
retrospective.json
```

模板位于 `playbook/templates/`。阶段未完成时保留 `draft`；门禁通过后才改为 `approved` 或 `locked`。`qa.json` 只有在全部阻断项通过并且最终结论为 `pass` 时，才允许把视频标记为可发布。

## 1. 选题

目标：明确核心问题、目标观众和看完后的单一认知。

输入：用户目标、产品或主题、平台、画幅、时长。

动作：

- 写出一句话核心问题。
- 写出主要观众和他们的痛点或欲望。
- 写出观众看完后只需要记住的一句话。
- 列出不能偏离的事实、限制和禁用方向。

产物：`brief.json`

门禁：

- 只有一个核心问题。
- 有明确观众和单一结论。
- 平台、画幅和时长明确。
- 没有用素材标题代替主题。

失败回退：

- 核心问题不唯一时先确认，不直接写脚本。
- 没有明确承诺时停止后续编排。

## 2. 参考

目标：找到 Design Reference，拆出可复用的结构和网感。

输入：`brief.json`、参考视频或参考链接、用户在 Studio 勾选的风格。

动作：

- 计算参考视频 SHA-256，先查 `style-library/index.json`。
- 抽取关键帧和时间结构。
- 记录钩子、节奏、信息密度、镜头关系、字幕层级和结尾方式。
- 记录哪些结构可以复用，哪些品牌、文案和素材禁止复制。

产物：`reference.json`、证据帧、风格库 ID 或明确的无风格声明。

门禁：

- 参考指纹和时间范围已记录。
- 至少完成一套结构拆解。
- 证据帧能指向具体时间点。
- 明确列出禁止复制项。
- 有勾选风格时，只读取 `HYPIT_STYLE_SELECTION.json` 中的已选风格。

失败回退：

- 没有参考时改为原创结构，并明确标记。
- 新参考与旧模板不同时，拒绝复用旧模板。

## 3. 素材

目标：围绕核心问题收集画面、案例、数据和对比。

输入：`brief.json`、`reference.json`。

动作：

- 按核心论点整理画面、案例、数据、对比和产品证据。
- 每一条论点绑定可追溯素材。
- 标记来源、授权和使用状态。
- 补齐开头、正文、证据和结尾所需覆盖。

产物：`material-plan.json`、素材清单。

门禁：

- 每条核心论点都有素材或明确的证据缺口。
- 没有未授权素材。
- 素材覆盖钩子、正文、证据和结尾。
- 静态抽帧不能冒充视频素材。

失败回退：

- 素材不足时先改脚本或补素材，不用无关画面填空。
- 授权不明时标记为不可发布。

## 4. 编排

目标：用 shotbook 安排每段内容、镜头、组件和时长。

输入：`brief.json`、`reference.json`、`material-plan.json`。

动作：

- 把脚本拆成有明确目的的镜头。
- 为每个镜头指定起止帧、画面、台词、组件、动效、声音和验收条件。
- 检查镜头之间的承接和节奏。
- 锁定总时长、画幅和帧率。

产物：`shotbook.json`

门禁：

- 每个镜头都有目的、素材、起止帧和验收条件。
- 没有空镜头、重复镜头或无归属镜头。
- 总时长、画幅和帧率一致。
- 镜头间的信息流连续。

失败回退：

- 编排与参考结构冲突时先修改 shotbook。
- shotbook 未定稿时，不进入组件和动效实现。

## 5. 组件

目标：从组件库调用标题、字幕、转场和版式，并记录版本。

输入：`shotbook.json`、`component-library/index.json`。

动作：

- 为每个镜头选择组件 ID 和版本。
- 记录组件覆盖值、素材替换和授权。
- 缺失组件先登记为 `planned`，不直接散落一次性代码。
- 检查品牌素材、字体和商标。

产物：`component-plan.json`

门禁：

- 每个组件 ID 都能在组件库找到。
- 交付使用的组件状态为 `verified`。
- 品牌素材、字体和商标已替换或标记不可发布。
- 组件参数可追溯。

失败回退：

- 组件不存在时先创建新版本并登记。
- 未验证组件只能用于探索，不能进入正式交付。

## 6. 动效

目标：用 HyperFrames 等工具完成动态包装。

输入：`shotbook.json`、`component-plan.json`、视频工程。

动作：

- 实现标题、字幕、转场、版式和贴纸动效。
- 对 HyperFrames 工程运行 `check`。
- 需要透明贴纸时输出 alpha WebM。
- 记录帧率、时长、分辨率、编码和文件大小。

产物：动效资产、渲染计划、真实渲染产物。

门禁：

- HyperFrames `check` 通过。
- 透明资产确实包含 alpha。
- 帧率、时长和画幅符合 shotbook。
- 没有未说明的空转或无效动效。

失败回退：

- WebM 丢失 alpha 时改用 PNG 序列加 alpha VP9 编码。
- 渲染失败时停在工程预览，不冒充成片。

## 7. 检查

目标：检查开头钩子、节奏、信息密度和表达准确性。

输入：`shotbook.json`、真实渲染产物、参考证据。

动作：

- 逐镜对照 shotbook 和参考结构。
- 检查前 3 秒钩子、节奏、阅读速度和字幕同步。
- 检查事实、数据、口播和字幕一致性。
- 检查音频、画幅、时长和素材授权。

产物：`qa.json`、对比图或接触表。

门禁：

- 所有必检项有状态和证据。
- 没有未解决的阻断项。
- 成片来自真实渲染文件。
- 未通过项只能标记为工程预览或待修复。

失败回退：

- 任一门禁失败时禁止发布。
- 发现事实错误时回到对应阶段修正。

## 8. 发布复盘

目标：记录完播、互动和可复用经验，反哺风格库和组件库。

输入：`qa.json`、发布结果或明确的未发布原因。

动作：

- 记录发布时间、平台、封面、标题和基础数据。
- 记录 24 小时、72 小时和 7 天指标。
- 记录留存曲线、评论反馈和异常情况。
- 把经验映射到 `style-library`、`component-library` 或 Playbook。

产物：`retrospective.json`、风格库或组件库更新建议。

门禁：

- 数据不可得时记录原因，不伪造数据。
- 每条经验必须指向可执行的复用或避免项。
- 没有真实验证前不得把风格标记为 `verified`。

失败回退：

- 未发布时记录未发布原因并关闭复盘。
- 数据异常时保留原始记录，不覆盖历史版本。

## 启动前校验

任务开始前运行：

```powershell
node playbook/validate.mjs
```

校验通过后，按照 `playbook.json` 的顺序执行，不得跳步。

已有工程阶段文件时，同时运行：

```powershell
node playbook/validate.mjs --project <工程目录>
```

该命令会检查阶段文件结构、shotbook 帧区间连续性、组件版本和已验证状态，并在正式 QA 结论为 `pass` 时要求成片文件真实存在且非空。
